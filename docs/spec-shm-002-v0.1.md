# SPEC-SHM-002 v0.1：个人账户、资产比较与 AI 复盘

**状态：待评审**
**交互依据：原型 v0.2**
本规格独立于 `SPEC-SHM-001`，不改变已有策略参数、股票池规则、历史研究结论或模拟账户。

## 1. 目标与首版边界

在现有 SHM 中增加一个手动记录的 USD 个人账户，将其表现与指定模拟账户、SPY 放在相同区间比较，并定期生成有证据依据的 AI 复盘。

首版交付：

- 期初建账，逐笔记录正股、ETF、期权、入出金、分红、利息及费用。
- 支持期权多空头、组合分腿、平仓、失效、实物交割及现金结算。
- 现金账户和保证金账户分别处理，允许如实记录融资和股票空头；不计算券商购买力或完整保证金。
- 提供周报、月报、手动报告及可交给开发 AI 的改进任务。
- 保留原模拟持仓、交易记录、运行日志、策略报告及调度入口。

多币种、券商自动同步、实时期权链、自动下单、自动调参和追加历史研究不进入首版。非标准调整合约允许暂存待核；未确认交付内容时不自动计算交割。

成功标准是**账目正确、比较口径一致、建议可追溯**，不以个人账户跑赢模拟或 SPY 作为功能验收条件。

## 2. 个人账本、估值与收益

### 2.1 数据输入

| 对象 | 必填字段 | 核心规则 |
|---|---|---|
| 账户起点 | 名称、USD、现金/保证金类型、期初日期与时点、净现金、持仓、券商净资产 | 从期初市值计算新观察期收益，不补造此前历史 |
| 期初持仓 | 证券或完整合约、方向、数量、单位估值、来源 | 股票允许碎股；期权整数张；空头数量为负，价格为正 |
| 普通交易 | 成交日期、时间、纽约时区、证券、方向、数量、价格、总费用 | 记录已发生事实；盘前盘后交易保留真实时间 |
| 期权合约 | 标的、Call/Put、到期日、行权价、乘数、结算方式 | 合约代码与拆分字段互相校验；标准乘数默认 100 |
| 期权交易 | BTO/STO/STC/BTC、张数、每股权利金、费用 | 明确开平仓；按完整合约合并校验可平数量 |
| 组合交易 | 组合编号、各腿完整信息、费用分摊 | 所有腿在一个事务中记账；展期是平旧仓加开新仓 |
| 现金事件 | 类型、金额、发生时间、说明 | 明确区分入金、出金、分红收入、利息收入、融资利息及费用支出 |
| 操作计划 | 理由、目的、退出条件、预计持有期、计划风险 | 可选；补写保留时间，不当作事前计划 |
| 每日估值 | 日期、覆盖时点、合约估值、券商净资产、来源及选择依据 | 明确快照覆盖哪些交易与资金流 |

原始平均成本、原始建仓日期为选填。未知时显示未知，不据此生成持仓天数或历史交易评价。

金额和价格使用 `Decimal`，API 以十进制字符串传递；计算过程中不按显示精度反复舍入。费用必须明确填写，允许为零。

### 2.2 校验与修订

- 拒绝非有限数、负价格、负费用、无效合约及未来成交。
- 成交不得早于账户起点；期权到期日不得早于成交日。历史补录按当时日期校验。
- 同一组合中的各腿共享可平数量，不能分别消耗同一持仓。
- 现金账户不得无依据形成负现金；保证金账户记录实际负债，并要求核对融资事实。
- 股票卖空、买回和平多头明确区分，不通过超量卖出静默改变方向。
- 期初对账容差为 `max($1, 券商净资产 × 0.01%)`；超出时须解决遗漏或明确记录应收、应付项目。
- 疑似重复成交提示核对；同一提交编号重复请求返回原结果，不重复记账。
- 修改已记账交易采用冲正与替代记录，保存原记录及修订原因，重算受影响的个人账本。
- 预览与提交之间账本发生变化时，要求重新预览，不按旧持仓确认。

### 2.3 期权及成本处理

确认区统一展示：

**原持仓 → 本次变化 → 成交后持仓**，以及净现金、本次交割义务变化、成交后交割总额。交割金额不能标成最大亏损或保证金。

固定记账规则：

- 买入权利金减少现金并形成多头资产；卖出权利金增加现金并形成空头负债。
- 普通平仓采用 FIFO，分摊开仓与平仓费用。
- 到期失效以确认事件关闭合约，不因缺报价或到期日期自动补零。
- 实物交割同时处理期权、股票与现金，先前权利金不再次产生现金。
- 行权或指派的权利金及相关费用计入对应股票成本或有效卖出收入，不再重复记作独立期权利润：Call 行权增加股票成本，Put 指派减少股票成本；Call 指派增加卖出收入，Put 行权减少卖出收入。
- 现金结算录入实际、未扣本次费用的有符号结算总额，关闭合约后另扣费用，不生成股票。
- 已转入股票的期权，不单独作为一笔“盈利/亏损平仓”统计；通过关联记录分析整组结果。
- 拆股、换股及调整合约必须有可核对依据；未解决时保留异常状态。

分红分别记录税前金额、扣税和净到账；再投资另记买入。负现金已代表融资时，不再重复扣减借款。

### 2.4 估值状态

以下三项独立保存、独立展示：

1. **账户收益依据**：持仓账本、券商净资产、未选定。
2. **持仓归因完整度**：完整、部分缺失。
3. **对账状态**：一致、有差额、不可计算。

缺少期权估值时，账本合计及对账差额不得伪造为已知值。用户可以确认券商总净值用于账户收益，但须确认对应入出金已完整录入；个股和期权归因仍可不完整。

差额超过容差时，提供“暂存待核对”或“采用指定来源并填写理由”。选择来源不等于完成对账。

正股使用实际价格，现金分红另行记账，避免含息复权价格与现金分红重复计收益。复用现有缓存中的名义价格字段；字段缺失时不拿总回报价格直接乘真实股数。

只刷新个人持有标的及必要的 SPY 数据，复用现有供应商限流和每日 **600 次**调用预算，模拟任务优先。期权首版采用人工券商估值，不增加全市场扫描。

### 2.5 收益比较

主指标为剔除外部资金流的时间加权收益及起点 100 净值。

- 开盘前现金流：`r = V_end / (V_start + C) − 1`。
- 收盘后现金流：`r = (V_end − C) / V_start − 1`。
- 盘中有现金流前后估值时分段链接；否则采用 Modified Dietz，明确标为近似。
- 多期累计：`R = ∏(1+r) − 1`。
- 入金、出金不算收益；真实费用、融资利息和分红扣税如实计入，并分别披露。
- 分母不为正、现金流不完整或估值缺失时，不输出看似正常的收益排名。
- 缺估值日曲线断开；区间内部缺数时，不宣称得到完整区间最大回撤。

默认比较个人账户、S500-C3 的 10 bps 账本及 SPY；可切换现存模拟版本和 25 bps 情景。起点取参与账户可比较的共同起点，截止同一完成交易日。

模拟账户尚无前向记录时，先展示个人账户与 SPY，并标明模拟账户等待状态；不得接入历史回测替代前向曲线。

SPY 采用股息再投资总回报，买入成本与所选模拟成本情景一致，费用计入首日，不通过归一化抹除；末日只估值。个人真实费用与模型成本不混称实测。未满一年以累计收益、相对 SPY 和实际回撤为主，不用短期年化宣布目标实现。

## 3. 界面、接口与存储

以原型 v0.2 为交互基线：

- 完整保留旧导航，新增个人账户、AI 复盘和 AI 设置。
- 持仓行操作带入对应证券与合约；通用录入明确选择方向。
- 已有合约自动带入；低频字段折叠，净现金和合计持仓常驻确认区。
- 切换类型、关闭重开保留本页草稿；账户和 API 密钥不写入浏览器持久存储。
- 手机持仓卡直接展示标的、数量、净市值及操作。
- 报告选择器展示类型、区间、所属账户及生成状态；个人和模拟统计随页签同步切换。
- 保存配置后跨页保持一致；修改接口、模型或凭据后，原测试结果失效。

复用现有 Python 服务、静态前端和日线缓存。新增独立 `portfolio.sqlite3`，保存个人账户、合约、事件、成本批次、估值版本、AI 配置、报告作业及建议状态；原模拟账本和 `service.sqlite3` 运行语义保留。

新增接口按以下职责划分：

| 接口 | 职责 |
|---|---|
| `/api/personal/account` | 读取、建立和修订期初账户 |
| `/api/personal/events/preview` | 校验交易、现金及生命周期事件，返回金额、合计持仓、错误和提醒 |
| `/api/personal/events` | 按账本版本、预览摘要和幂等编号提交事件；提供流水读取及修订 |
| `/api/personal/valuations` | 读取、预览和保存估值及来源选择 |
| `/api/comparison` | 返回指定区间的账户曲线、SPY、费用口径和完整度 |
| `/api/ai/settings`、`/api/ai/test` | 配置及最小连接测试；读取时不返回密钥 |
| `/api/ai/reports` | 创建、列出及读取报告作业与版本 |
| `/api/ai/suggestions` | 更新建议状态、导出实施任务 |

预览不记账。正式提交在事务中重新校验；版本变化或幂等编号对应不同内容时返回冲突，前端保留输入并要求重新预览。现有 `/api/dashboard` 的模拟数据接口保持兼容。

## 4. AI 报告、配置与访问

### 报告要求

先由程序计算指标和证据包，再交给模型解释。报告包括：

- 数据覆盖、估值缺口、未确认期权事件和对账差异。
- 个人持仓集中度、操作频率、持有期、费用、盈亏分布、计划遵守及期权习惯。
- 模拟策略的规则执行、退出信号、次日成交、跳空和模型费用差异。
- 最多三条优先建议，区分工程/数据改进、个人操作改进、待验证策略假设。
- 上次建议的状态和证据变化，减少重复建议。

每条建议包含：事实、证据引用、替代解释、不确定性、建议动作、修改范围、验收方式及停止条件。量化事实引用程序生成的指标；证据不足时缩小结论范围，标题不得超出正文证据。

不生成交易人格评分，不把事后补写当事前纪律，不让短期收益触发自动调参。AI 不修改代码、账本、研究结论或订单。“采纳建议”仅改变待办状态；导出生成 Markdown 实施任务。

报告保存数据截止日、账本版本、策略版本、模型、模板版本、输入摘要与哈希、用量和建议状态。历史报告不因账本修订而被静默改写；修订生成新版本。

### 接口与周期

首版使用 OpenAI 兼容 Chat Completions：

- 配置 Base URL、密钥、精确模型 ID、周期、发送范围及调用限额。
- 测试只发送无持仓短样例；不依赖服务商一定提供 `/models`。
- 默认使用 `max_completion_tokens`；仅在连接测试明确返回不支持该参数时尝试 `max_tokens`，保存测试通过的兼容方式。
- 不发送工具调用、外部检索或不必要的模型参数；返回 JSON 经结构和引用校验后才能成为正式报告。
- 接口失败、截断或引用无效显示失败/受限状态，不伪装成完整报告。

默认北京时间周六 **08:00** 生成上一周简报，每月 **1 日 08:15** 生成上一个自然月复盘。新建账户不足整月时明确标为部分月份，不计入完整月验收。

自动生成按账户、区间、报告类型、模板版本去重。每月默认最多 **8 次自动调用尝试**，重试计入额度；暂时性失败最多重试一次。每次默认最多 **6,000 completion tokens**，输入包上限 **200,000 字符**；超限明确提示，不静默截断后宣称完整分析。手动报告最多每日四次尝试。

无新数据时跳过重复调用。报告任务使用独立队列与执行线程，失败、限流或超时不影响每日策略任务。服务商未提供单价时只显示用量及“费用未知”。

### 密钥与认证

按已选择的方式，**复用现有认证网关及 HTTPS，不另建用户账号体系**。

- 网关通过认证后才转发私人接口；后端验证网关专用的服务间凭据，不能仅相信浏览器可伪造的认证标记。
- 原端口直连不得绕过个人账户和 AI 接口的保护；旧模拟接口不混入私人数据。
- 网关公开地址和服务间凭据作为部署配置提供。未配置、未通过绕过测试时，私人功能保持关闭。
- AI 密钥在 NAS 服务端加密保存，主密钥与数据库分离；日志、浏览器响应、报告及导出不包含密钥。
- 发送前移除账户名、券商账号及非必要标识；交易数据仍按敏感业务数据处理。
- 关闭自动发送保留周期设置；更换目的地或模型后重新测试。
- 报告渲染禁用原始 HTML 和外链图片；交易备注只作为数据，不作为系统指令。

## 5. 验收、交付与停止条件

### 必须通过的固定场景

1. 期初正股、期权多空头与现金能对账，期权每股价格误填为每张金额时能定位差异。
2. 入金不增加投资收益，融资利息明确减少现金和收益。
3. 卖出期权同时增加现金与负债；平仓、失效、行权、指派不重复计权利金。
4. 同一合约被组合多腿超量平仓时阻止确认；部分平仓和展期保持关联。
5. 从 MSFT 行进入始终带入 MSFT；类型切换与关闭重开不丢本页草稿。
6. 券商净值可用但合约缺价时，不显示“账本已对账”；有差额时必须选择处理方式。
7. 缺数、陈旧报价、未确认公司行动不制造收益曲线；费用和基准区间一致。
8. 重复提交、重启、历史修订不重复记账；并发修改要求重新预览。
9. 个人和模拟报告使用各自样本；缺数据时标题和结论同步受限。
10. 设置跨页保持，连接变更使测试失效；关闭发送后不再自动调用。
11. 未登录、伪造认证标记和原端口直连不能读取或修改私人数据。
12. AI 失败不阻塞模拟任务，原 V04、S500-C3 和历史研究记录保持独立。

### 实施与交付顺序

1. 个人账本、生命周期和估值对账。
2. 同区间收益比较与原型 v0.2 界面接入。
3. 受保护的 AI 设置、报告作业及建议导出。
4. 备份后部署，使用独立验收账户完成闭环，再开启真实个人账户入口。

交付 SPEC、变更 ADR、数据库版本迁移、操作说明及固定样例验收记录。回滚代码或关闭新功能时保留已录个人账本。

完成上述流程和验收后结束首版；不因收益不佳扩展参数搜索、历史股票池研究或新分析模块。
