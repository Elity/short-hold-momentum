# P3 期权覆盖层规则手册

本覆盖层只把已经存在的正股信号转换为有限风险的模拟订单。它不产生独立选股信号、不做历史期权回测，也不连接任何实盘下单端点。

## 允许的结构

- 备兑看涨（covered call，CC）：只能针对已经持有的股票，每完整 100 股卖出 1 张 call。不足 100 股不下单，余下不足一手的股份不被期权覆盖。
- 现金担保卖出看跌（cash-secured put，CSP）：只能针对排名 `top_n+1` 至 `top_n+5`、且当前未持有的候补股；每只候补最多卖出 1 张 put。
- 禁止买 call、买 put、垂直价差、裸卖期权、融资或卖空。历史期权回测留待有合格历史数据的后续版本。

## 可行性提示

Gate 资金范围是 5–10 万美元，`top_n = 15` 时单仓通常只有约 3,333–6,667 美元。CC 要求至少 100 股，因此通常只有股价不高于“单仓金额 / 100”的少数持仓可用。期权覆盖层是可选收入来源，不是策略核心；没有合格合约时直接跳过。

## 到期日与合约选择

每次换仓在 `t+1` 成交后生成草稿。对每个标的，通过已安装的 yfinance `Ticker.options` 读取到期日，选择不早于下一换仓日的第一个标准月度到期日（当月第三个星期五），再用 `Ticker.option_chain(expiration)` 读取延迟期权链。

CC 的选择顺序：

1. 仅考虑 `bid >= 0.10` 美元且 `(ask - bid) / mid <= 20%` 的 call。
2. 在 delta 不高于 0.30 的合约中选择最低行权价。
3. yfinance 链不提供 delta 时，代码优先用链上的 `impliedVolatility` 计算本地 Black–Scholes delta；IV 也缺失时才采用规格中的兜底，选择至少 5% 价外的最低行权价。

CSP 的选择顺序：

1. 对候补股按原排名依次处理，只考虑 `100 × strike` 不超过尚可锁定现金的 put。
2. 按 ADR-008，仅保留 `bid >= 0.10` 美元且 `(ask - bid) / mid <= 20%` 的报价，避免零权利金或过宽价差订单。
3. 使用绝对 delta 不高于 0.25 的最高行权价（即满足阈值时最接近现价者）。
4. CSP 没有规格授权的“5% 价外”兜底；链上 delta 和可计算 IV 都缺失时必须跳过。

SPEC-SHM-001 §4.12 只为 CC 明确规定了 bid 与价差门槛；首次延迟链干跑实际选出了 bid 为 0 的 CSP，因此 ADR-008 将相同门槛扩展到 CSP。后续若要调整阈值，必须另写 ADR，不能按结果回改。

本地 Black–Scholes delta 只用于合约筛选，不把理论价当成交价。这是为补足 yfinance 不返回 delta 而引入的 P3 工程假设，P4 开始前应在 ADR 中接受或替换。假设明确固定为：欧洲式公式、日历天数 / 365、默认无风险利率 0、默认股息率 0；调用方可显式传入利率和逐股股息率。波动率来自 yfinance 的 `impliedVolatility`。这些近似和延迟报价都必须在 P4 前向验证中保留为模型偏差来源。

## 风险与资金公式

以每张合约 100 股计：

- CC 最大亏损：`max(0, 股票成本价 - 收取权利金) × 被覆盖股数`。
- CC 上行封顶价：call 行权价；现金占用为 0。
- CSP 最大亏损：`max(0, put 行权价 - 收取权利金) × 100`。
- CSP 现金占用：`put 行权价 × 100`，从生成订单时起按 100% 锁定。

组合必须同时满足：

- 每张 CC 有 100 股现货覆盖；
- CSP 总名义金额不超过组合净值的 20%；
- CSP 总现金占用不超过可用现金；
- 全部 CC 与 CSP 的合计最大亏损不超过组合净值。

任何一项不满足，相关组合或新增 CSP 必须拒绝，不生成不受覆盖的订单。

## 示例

持有 AAA 250 股、成本价 50 美元，选择行权价 55 美元、bid 1.50 美元的 call：只卖 2 张，覆盖 200 股；最大亏损为 `(50 - 1.50) × 200 = 9,700` 美元，上行封顶价为 55 美元，剩余 50 股不卖 call。

候补 BBB 的合格 put 行权价为 45 美元、bid 1.20 美元：卖 1 张需要锁定 4,500 美元，最大亏损为 `(45 - 1.20) × 100 = 4,380` 美元。加入前仍要重新检查 20% CSP 上限、可用现金和组合最大亏损。

## 模拟订单单

`paper_ticket_rows` / `write_paper_ticket_csv` 只生成 §4.13 的六列草稿：`ticker, side, qty, order_type, time_in_force, reason`。`ticker` 使用期权合约代码，方向固定为 `sell`，订单类型为 `limit`，`reason` 记录策略、标的、到期日、行权价、bid 和 delta 来源，并明确写入 `paper_only`。本模块没有下单方法，也不得被用于实盘提交。

干跑输入必须由调用方明确提供账户净值、可用现金、真实持股股数、成本价、现价、候补排名、下一换仓日与估值日。当前模型名单或回测净值不能被当作真实账户持仓或 Gate 资金选择。
